# 0.4 Microtransactions, anti-cheat and game sessions

Version 0.4.0 binds 38 additional routes across six interfaces. Coverage is now
161 routes across 30 interfaces: 151 explicit documented routes and ten inherited
Sandbox routes. The [inventory](api-inventory.json) records each binding and its
version. These are locally tested protocol bindings; live Publisher integration
and production operation remain separate validation steps.

Publisher keys also satisfy the client's user-key kind check. Steam still checks
ownership, delegated permissions, enabled features and app access. Local key-kind
validation cannot establish those permissions.

## Payments and reconciliation

Select `client.micro_txn_sandbox()` or `client.micro_txn_production()` explicitly.
The two prefixes share one implementation and never fail over between databases.
The [read-only example](../examples/query_sandbox_transaction.rs) queries a known
Sandbox transaction; it performs no purchase, capture or refund.

All payment responses require a string `response.result` equal to `OK`. Missing
or malformed acknowledgements fail decoding, while explicit business failures
remain API errors. An acknowledgement establishes request acceptance, not
settlement or entitlement. Opaque responses retain unknown transaction statuses,
chargebacks, fraud markers and partial refunds for application-owned decisions.

The [implementation guide](https://partner.steamgames.com/doc/features/microtransactions/implementation)
separates initiation, user authorization and finalization. Persist the merchant
order ID before submission. Finalize only after authorization; a browser return
alone does not prove approval. Uncertain initiation requires following Valve's
new-transaction guidance; uncertain finalization requires QueryTxn/GetReport
reconciliation. Every mutation is sent once, including when an order ID exists.

Amounts remain signed integers with their documented widths. `amount[i]` is the
complete line total, not a unit price multiplied by the crate. Steam uses
hundredths for every currency, including JPY and KWD; application conversion must
follow the [current currency rules](https://partner.steamgames.com/doc/store/pricing/currencies).
The crate checks currency-code shape without freezing Steam's market list or
currency-specific increments. Cart counts derive from the supplied slices;
descriptions/categories use Unicode character limits. Language accepts supported
forms such as `zh-CN`, `pt-BR` and `es-419`.

Recurring terms are grouped to prevent partial field sets. ProcessAgreement's
acceptance starts billing; it does not prove a successful charge. A canceled
agreement does not by itself establish when paid entitlement expires. Reconcile
payment events using the [recurring-billing guidance](https://partner.steamgames.com/doc/features/microtransactions/recurring_billing).
Zero order IDs remain valid for the documented Steam Store subscription cases.

GetReport is an entitlement-reconciliation feed, not a financial statement.
Its timestamp cursor preserves fractional precision. Follow the latest returned
update timestamp even after a short batch; keep the cursor on empty batches.
The caller controls polling, deduplication, persistence and fulfillment. Returned
authorization URLs are never followed by this client.

## Reports, bans and VAC status

ReportPlayerCheating records an accusation. Authenticate the reporting parties,
review evidence, then explicitly call RequestPlayerGameBan with the original
report ID if justified. There is no automatic report-to-ban pipeline. Permanent
bans require `GameBanDuration::Permanent`; a zero-second temporary ban is invalid.
Positive durations retain the full uint32 range. Report-query cursors and optional
filters are forwarded without synthesizing pagination or defaults.

RequestVacStatusForUser has an endpoint-specific policy: `success=false` can mean
VAC is pending. Only that boolean in its canonical `response` envelope receives
this exception; explicit errors and unrelated response envelopes remain strict.
`success=true` with `session_verified=false` is still unverified, and an absent
verification field remains absent. Later VAC timeout events can invalidate an
earlier result. The binding does not infer matchmaking authorization.

The VAC reference describes scalar semantics without a complete JSON wrapper
example. VAC and EndSecureMultiplayerSession use the canonical Service `response`
wrapper; credentialed wire validation of that choice is pending. Other incomplete
schemas remain opaque. Valve must manually enable the Web API secure-session
methods, which are intended for games authenticating independently of Steam.
Games using Steam Authentication must follow its native P2P or game-server flow.

Community reports preserve exact field casing (`steamidActor`, `steamidTarget`,
`abuseType`, `contentType`). Undocumented enum values stay numeric. Submitting a
report does not establish a moderation decision.

## Notification sessions and lobbies

UpdateSession's prose describes replacement, including removing omitted users.
Its optional fields retain omission versus explicit empty values; callers must
construct updates with replacement semantics in mind. GetSessionDetails preserves
its nested session selectors. Undocumented localization, user and message objects
retain their fields with redacted Debug output.

Despite its name, DeleteSessionBatch documents one scalar `sessionid`; the binding
does not invent an ID array. Notification requests, updates and deletion are
explicit calls, without automatic background polling or cleanup.

CreateLobby follows the documented `lobby_type` field rather than the example's
inconsistent `lobbytype` spelling. Type 4 reuses a named unique lobby and replaces
its allowed-members list; an explicit empty list removes all reserved slots.
Metadata pairs and full-width Steam IDs remain intact. Lobby Web API operations
do not reproduce native SDK joining, callbacks or presence tracking.

## Validation and distribution

Local tests cover every route, verb, credential kind and encoding, with write
non-replay, read retries, exact integer fields, response errors, pending VAC
states and reconciliation boundaries. No live payment, ban, community report,
notification or lobby mutation was performed. Production permissions and actual
outcomes require credentialed validation.

Maintenance uses Rust xtask and the repository contains no Python source. Cargo's
include allowlist retains library sources, runnable examples, bilingual README/
changelogs and licensing. Tests, benchmarks, xtask, workflows, these documents and
reference inventories stay on GitHub. Archive-policy checks and a separately
extracted package build verify this boundary.

Local checkpoint on 2026-10-21 with stable Rust 1.99.1: 168 workspace tests,
formatting, strict Clippy, warning-free rustdoc, dependency audit including
prereleases, archive policy and an independently extracted 48-file package build
passed. The Rustls preview compatibility exception is recorded in
[dependencies.md](dependencies.md). Cross-platform CI is a separate result.
