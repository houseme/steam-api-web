# 0.5 分支 Review 与共享数值解码

[English](review-0.5.md) | 简体中文

核对日期为 2026-10-22，范围从 main `e54b0fc` 到 `0a4617b`，覆盖财务凭据、六个
P4 调用方、响应模型、日期验证、覆盖工具、打包及 CI。审查与重构在已有隔离分支中
完成，并使用专属 Cargo target 目录。

## 发现与重构

P4 复用共享传输、编码、响应校验及有界读取重试，
不需要整体重写。Financial 权限与其他 key 类别隔离，广播写入保持单次发送，日期
校验已经集中处理。后文全局复核修复了依赖特性统一导致合法大数统计被误拒绝的问题，
保留共享架构。

**信息项：重复整数解析与字符串分支试探。** 财务报表新增了 untagged 数字/字符串
解析器，与 `types` 中已有的无符号解析器重复；Cloud 另有局部可选整数包装。
untagged 解码先缓存标量并尝试数字分支，带引号的整数会在失败后进入拥有 String
的分支。

现在由一个共享 Serde Visitor 处理必填和可选的 `u32`、`u64`、`i32`、`i64` 字段。
十进制文本直接从 `&str` 解析，数字输入采用检查转换，省去分支重试和中间字符串复制。
财报行/游标、Steam ID、Cloud ID、评论 ID、用户组 ID、站点 ID 均复用此路径。
可选字段缺失、null、零、有符号极值及完整无符号范围的含义保持不变；浮点、非法
文本和溢出仍报错。公开类型与签名不变，`StatValue` 保留独立的浮点数契约。

覆盖工具有意检查模块导出、方法声明及准确路径常量，不解析 Rust AST，输出已经说明
其静态映射边界。没有证据支持引入编译器前端、替换传输缓存或新增同步依赖。

## 复跑测量

```sh
cargo bench --bench integer --locked --offline
```

参考解析器从 `0a4617b` 提取到 `benches/support/integer_v050.rs`；候选直接编译
`src/types.rs`。每次操作解码 100 个有符号或无符号标量，包含零与宽度极值。数字和
十进制字符串 fixture 在计时前验证结果等价。直接 JSON 解码与客户端的
JSON→Value→类型解码均计入解析和输出析构，计时区不添加输入克隆或 fixture 构造。

每项预热 100 次，执行九轮 A/B/B/A，每样本 2,000 次操作；报告各实现 18 个样本的
中位数，基线漂移超过 10% 则拒绝解释结果。一次本地 stable Rust 1.99.1、优化 Cargo
bench profile 的有效结果如下：

| 标量 / 路径 | 参考 ns/op | 当前 ns/op | CPU 耗时减少 | 基线漂移 |
| --- | ---: | ---: | ---: | ---: |
| 有符号数字 / 直接 | 1,618 | 1,221 | 24.6% | +0.4% |
| 有符号数字 / Value | 2,073 | 1,748 | 15.7% | +1.0% |
| 有符号字符串 / 直接 | 13,821 | 2,058 | 85.1% | -1.1% |
| 有符号字符串 / Value | 14,614 | 3,150 | 78.4% | +0.0% |
| 无符号数字 / 直接 | 1,513 | 1,132 | 25.2% | +0.8% |
| 无符号数字 / Value | 1,965 | 1,656 | 15.7% | +1.7% |
| 无符号字符串 / 直接 | 17,241 | 2,446 | 85.8% | +2.2% |
| 无符号字符串 / Value | 16,996 | 3,600 | 78.8% | +1.9% |

这些数字只覆盖标量解码，不代表完整报表、HTTP 吞吐或 Steam 生产时延。JSON Value
解析仍拥有输入字符串；重构消除的是类型化整数解码内部的再次复制。计时没有统计分配
次数，也不能证明全局最优实现。

## 刷新 main 后的全局复核

2026-10-22 执行 `git fetch origin` 和 `git merge origin/main`，结果为
`Already up to date`：main `e54b0fc` 已是 `e051ee0` 的祖先，无需额外 merge commit
或改写历史。本轮按完整请求生命周期复核，不将 P4 模块当成孤立代码处理。

| 共享路径 | 决策与依据 |
| --- | --- |
| 并发、节流、冷却与重试 | 保留统一发送边界；许可覆盖节流与响应读取，退避释放许可，写入保持单次发送，主机固定。已有协议测试覆盖这些行为。 |
| 请求编码 | 保留直接写入表单/Service JSON 和索引键栈格式化。尝试 `url::form_urlencoded::byte_serialize` 后，小表单与混合字节发生回退；即使长段免转义字节有所提升，仍撤销该方案。 |
| 响应处理 | 保留一次 JSON 解析和类型化/opaque 数据消费前的共享业务错误遍历。直接反序列化类型本身无法覆盖必要的错误 envelope、opaque 和未知字段。同步解码由响应大小/解析深度约束，Tokio timeout 无法抢占 CPU 的边界已在设计文档说明。 |
| 线上标量 | 整数继续使用检查转换的 Visitor，`StatValue` 使用独立数值 Visitor；整数拒绝浮点，统计保留有限浮点和 Number 的特性精度。它们是两种线上契约，不是两套传输层。 |

`StatValue` 是公共协议标量层剩余的数字/字符串试探解析器，全局汇总、用户统计和
schema/成就默认值均复用此类型。新 Visitor 直接处理无符号、有符号、有限浮点和
借用数值文本；Number 的 map 表示交回其自身反序列化器，保留下游
`serde_json/arbitrary_precision` 特性统一行为，不依赖私有字段名常量。默认行为、
负零、整数边界、指数形式和 JSON 序列化保持兼容，未引入运行时、通用框架、新依赖
或传输开关。

**轻微正确性问题：特性统一后的合法大数被拒绝。** 下游启用
`serde_json/arbitrary_precision` 时，数值统计
`340282366920938463463374607431768211455` 可解析为合法 Number；但 Value→类型
阶段会以 u128 传递，旧 untagged 缓存 Visitor 在 Number 接收前就拒绝它，使客户端
返回 Decode。使用原始解码器的独立复现确认旧实现失败，新实现精确保留该值。新
Visitor 将 128 位标量及 Number map 表示交回 Number 自身；测试通过客户端使用的
拥有 Value 路径，以及直接/借用解码，覆盖 u128::MAX、i128::MIN 和长小数精度。

### 完整响应测量

```sh
cargo bench --bench integer --locked --offline -- --statistics-only
```

标量参考实现来自 `e051ee0` 的原始 StatValue 解码器。完整响应直接编译生产
`response`、`error` 模块并使用公开 `GlobalStats` 模型；参考模型保留相同字段、
可选 total、BTreeMap 和 flatten 未知元数据，仅替换旧标量类型。计时前比较 total、
结果码和未知字段。每份响应含 100 个混合有符号/无符号/浮点统计及保留元数据，输入
构造不计时，JSON 解析、业务校验、envelope 选择、模型构造与析构均计入，不执行 HTTP。

stable Rust 1.99.1、优化 profile、九轮 ABBA、中位数与 10% 漂移门槛：

| 场景 | 参考 ns/op | 当前 ns/op | CPU 耗时减少 | 基线漂移 |
| --- | ---: | ---: | ---: | ---: |
| 数字标量 / 直接 JSON | 1,682 | 1,174 | 30.2% | -7.0% |
| 数字标量 / Value | 1,952 | 1,632 | 16.4% | -0.0% |
| 字符串标量 / 直接 JSON | 14,167 | 2,039 | 85.6% | +1.4% |
| 字符串标量 / Value | 14,774 | 3,348 | 77.3% | -0.6% |
| 完整数字响应，6,166 字节 | 41,485 | 41,141 | 0.8% | -0.0% |
| 完整字符串响应，6,366 字节 | 56,561 | 44,133 | 22.0% | +0.1% |

完整数字响应受 DOM/map 工作主导，0.8% 差异视为基本持平；完整字符串响应仍有明确
CPU 收益。这些结果不代表网络吞吐或全局最优。被否决的标准字节编码器在本地反例
实验中让小标量表单慢约 42%、4 KiB 任意字节慢约 127%，对应实现未保留。
