# 0.3 Cloud, inventory, economy and Workshop contracts

English | [简体中文](p2_ZH.md)

Version 0.3.0 adds all 66 documented P2 methods in 12
interfaces, bringing coverage to 123 methods across 24 interfaces. The
[machine inventory](api-inventory.json) records each P2 Rust method and the
verbatim `v0001` item-definition path. These are protocol bindings with local
tests; credentialed Steam integration and production operation remain separate.

## Cloud and remote storage

[ICloudService](https://partner.steamgames.com/doc/webapi/ICloudService) requires
user-granted `read_cloud` or `write_cloud` OAuth scopes. Configure a public-host
client and pass `cloud::OAuthAccessToken`; an API key does not replace that
permission. The token is encoded outside `input_json`. The secret and returned
signed URLs/provider headers have redacted Debug representations.

Every Cloud method requires `x-eresult: 1`. Missing, malformed or duplicate result
headers fail decoding, while a non-success result becomes a business error. Only
Delete and CompleteAppUploadBatch accept an empty HTTP 200 body after checking
that header. Other methods require their documented typed result. This is a
different response policy from SetAppBuildLive's optional HTTP 201 body.

An upload sequence is caller-managed:

1. BeginAppUploadBatch declares the intended uploads/deletes and returns a batch ID.
2. BeginHTTPUpload returns provider destination and header instructions.
3. The caller performs the file PUT with a separate HTTP client and the specified headers.
4. CommitHTTPUpload reports the actual transfer outcome; `file_committed=false` remains a failed stage.
5. CompleteAppUploadBatch must be attempted after all operations, including failures.

The Steam client never follows returned transfer URLs or forwards its API keys
or OAuth token to them. It does not run cleanup from Drop, promise eventual
completion, or treat obtaining an upload plan as file persistence. Cancellation
and ambiguous failures require application-owned reconciliation and batch cleanup.
The optional `is_public` field follows Valve's example, which omits it from the table.

The [Cloud example](../examples/cloud_files.rs) reads one metadata page without
printing private names or signed URLs. Cloud enumeration uses `start_index` and
`total_files`; callers control pagination. The seven
[ISteamRemoteStorage](https://partner.steamgames.com/doc/webapi/ISteamRemoteStorage)
methods cover UGC metadata, collections and subscriptions, with indexed IDs and
derived counts. They preserve opaque results where schemas are unspecified.
Returned file bytes remain a separate transport responsibility.

## Inventory and definition administration

[IInventoryService](https://partner.steamgames.com/doc/webapi/IInventoryService)
requires a Publisher key with Steam Economy permission. Requests use `input_json`;
ModifyItems follows the explicit example by placing appid outside it. Integer
IDs remain lossless, ConsumeItem quantities use decimal strings, and returned
`item_json`/`itemdef_json` text stays unchanged in the opaque result.

Grant/promo/consume request IDs are supplied and persisted by the caller, never
generated or replaced by the crate. Steam deduplicates eligible operations; an
ID alone does not make every failure safe to retry. Mutations never replay
automatically, even with an ID. Crafting materials pair IDs and positive quantities;
Steam still determines recipe eligibility, atomicity and ownership.

ModifyItems carries the caller's concurrency timestamp and allows one typed
property value or removal per item/property. Its limit is 100 distinct items,
not 100 update rows. Signed integers and finite f32 values retain their documented
integer/string encodings. Steam validates stale timestamps and the final dynamic
property size because existing state is unavailable to this client.

AddItem's optional prose overrides inconsistent required markers. GetItemDefs
retains the documented scalar uint64 filters instead of guessing arrays from
plural names. See the source types for defaults and explicit omission behavior.

[IGameInventory](https://partner.steamgames.com/doc/webapi/IGameInventory) uses
flat parameters. UpdateItemDefs preserves the exact `/v0001` spelling and accepts
definition objects as JSON. Its example has an object-valued `result` envelope;
shared validation checks nested errors while retaining strict scalar EResult
handling. Partial `updated`/`failed` outcomes remain visible and must be inspected.
Cache flushing is a separate explicit operation.

## Economy, trades and market

[ISteamEconomy](https://partner.steamgames.com/doc/webapi/ISteamEconomy) uses
flat fields such as classid0/instanceid0 and assetid0/assetquantity0. Opaque asset
and transaction identifiers preserve their spelling. Monetary strings/numbers
are retained without conversion through floating point. GET StartTrade changes
state and is sent once, as are transaction initiation/finalization POSTs.

[IEconService](https://partner.steamgames.com/doc/webapi/IEconService) and
[IEconMarketService](https://partner.steamgames.com/doc/webapi/IEconMarketService)
use `input_json`. Trade-history continuation preserves the previous time and
full-width trade ID. Offer filters are forwarded without invented mutual
exclusion; active/cutoff and historical selection can overlap. The reference
does not document a GetTradeOffers cursor, so none is invented. Cache mutation
and listing cancellation require Publisher credentials and do not replay.

## Workshop queries, subscriptions and moderation

[Published-file queries](https://partner.steamgames.com/doc/webapi/IPublishedFileService)
offer explicit page or cursor selection. Cursors remain opaque; page mode is
bounded to 1..=1000. GET Delete is a mutation and never replays. Metadata,
tags, bans and incompatible-state updates preserve their independent contracts.

The [search](https://partner.steamgames.com/doc/webapi/ISteamPublishedItemSearch)
and [voting](https://partner.steamgames.com/doc/webapi/ISteamPublishedItemVoting)
interfaces use legacy indexed forms. ResultSetSummary retains its documented
64-bit appid. [Moderation](https://partner.steamgames.com/doc/webapi/IPublishedFileModerationService)
pins approval decisions to revision 2 with the original change number, leaving
stale-content rejection to Steam.

[Workshop payment/localization](https://partner.steamgames.com/doc/webapi/IWorkshopService)
contains nested messages without published field schemas. Borrowed JSON objects
or arrays of objects preserve those messages without fabricating their contents.
Revenue intervals preserve the service's half-open date range; the reference
does not justify inventing a UTC timezone. Opaque response acceptance never
implies that a payment rule, description or moderation decision persisted.

## Validation and distribution

Every P2 method has local fixtures for its endpoint, method, credential, encoding
and errors, plus replay tests, full-width identifiers and relevant stage/cursor
boundaries. No live Cloud files, inventory, trades, listings or Workshop content
were changed. Applications must validate scoped permissions and actual outcomes.

All maintenance remains Rust xtask; no Python is needed. The package include
allowlist retains library sources, examples, licensing and bilingual README/
changelogs. Integration tests, benchmarks, tools, workflows, these documents and
reference JSON remain on GitHub. Archive-policy and independently extracted
build checks validate that boundary. Repository checks also compare declared
coverage/version with the inventory and public Rust modules.

Local checkpoint on 2026-10-21 with stable Rust 1.99.1: 128 workspace tests,
formatting, strict Clippy, warning-free rustdoc and an independently extracted
42-file archive build passed. Remote platform CI is a separate validation result.
