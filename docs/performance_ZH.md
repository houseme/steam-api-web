# 传输层 Review 与编解码测量

[English](performance.md) | 简体中文

核对日期为 2026-10-21，范围是从 v0.1.0 到 8b7613a 的 0.2 开发改动，包括共享传输层、全部 P1 调用方、维护命令及打包和工作流边界。接口实现遵循一致的传输契约；共享编解码路径存在逐步累积的复制和端点开关。本次针对这些路径重构，公开方法签名保持兼容。这些证据不能证明全局最优设计或 Steam 生产可用性。

## 发现与实现

| 被核查版本中的具体问题 | 重构措施 |
| --- | --- |
| `client::param` 先拥有每个键和值，`encode_form` 再复制进另一个缓冲区；POST 又复制一次完整表单。 | `request::Params` 直接构造最终表单，原始字节从借用的切片编码；POST 接收缓冲区所有权。 |
| Service JSON 有分散的序列化路径，公共辅助函数位于 player 模块，游戏服务器请求还先构造中间 `Value`。 | 全部 Service 使用 `Params::json` 和借用字段的请求结构体，JSON 直接写入百分号编码器。 |
| `call_with_status` 从借用的 `Value` 反序列化，复制字符串并重建不透明 JSON；选择标准 envelope 时又重复检查错误。 | `response::Response` 将选中的 JSON 所有权交给类型化解码；不透明响应直接接收原有 JSON 容器。标准 envelope 检查一次，其他选中 envelope 和兄弟错误仍会校验。 |
| `Endpoint::auth(..., post)` 同时表达认证和管理写入，独立布尔值分别控制 HTTP 方法、重放和空响应。 | 使用命名的读取 GET、单次 GET、POST 操作统一方法与重放选择；空 HTTP 201 由明确的响应体策略控制。 |

并发许可仍覆盖限速等待和完整响应读取。如果在获取许可前完成限速，排队可能使实际发送时间集中，破坏配置的最小间隔。重试在退避期间释放许可，取消会自动释放。共享冷却、有限重试、截止时间、AWS-LC 隔离及敏感信息脱敏继续由协议测试覆盖；没有基于推测替换同步机制或运行时。

## 复跑测量

在 Git checkout 中执行：

```sh
cargo bench --bench codec --locked --offline
```

基准直接编译生产请求和响应模块。参考编码器及业务错误检查来自 8b7613a，参考响应解码在合法 fixture 上使用此前的借用反序列化算法。不透明包装与库具有相同的 `Value` 表示及透明 Serde 行为。两种实现都不执行网络请求。

每项先预热 100 次，再交错执行九轮 A/B/B/A，报告各实现 18 个样本的中位数。响应测量解析同一份包含 100 个游戏、60,704 字节的 fixture，并计入输出析构。计时前校验表单与响应结果等价；Service JSON 比较忽略不属于协议契约的对象键顺序。

一次本地 stable Rust 1.99.1、优化 Cargo bench profile 的结果：

| 场景 | 原实现 ns/op | 当前实现 ns/op | 耗时减少 |
| --- | ---: | ---: | ---: |
| 普通表单 | 262 | 111 | 57.5% |
| Service JSON 表单 | 474 | 144 | 69.7% |
| 类型化响应，包含解析 | 26,235 | 22,983 | 12.4% |
| 不透明响应，包含解析 | 33,006 | 21,219 | 35.7% |

这些是本地 CPU 测量样本，不能换算成端到端吞吐承诺，也不作为 CI 耗时阈值。网络延迟、API 配额、响应形状和分配器行为都会影响应用结果。计时没有统计内存分配次数；另有回归测试验证类型化字符串及不透明数组的原有存储直接转移。

## 验证与分发

新增五项针对性测试，覆盖 JSON 转义及类型、序列化错误脱敏、类型化字符串所有权、不透明容器存储，以及选中/兄弟/缺失 envelope 的失败路径。连同原有协议、TLS、维护和文档测试，workspace 共通过 80 项测试。严格 Clippy 同时编译基准；打包检查确保基准、参考算法及本文留在仓库，仅新增生产模块进入发布 crate。
