# 全局请求链路审查与实测重构

[English](review-global.md) | 简体中文

2026-10-22 基于合并后的 main `9d2cab1`，审查共享传输、请求编码、响应校验、
数值模型以及上一轮 API/示例交付。使用 Rust edition 2024、stable 1.99.1；依赖
继续从根 workspace 继承。全部 33 个接口族、160 个公开异步方法保持 API 兼容。

## 结论与范围

现有共享架构是连贯的：接口适配器选择固定契约，统一客户端承担鉴权、超时、
并发、请求节奏及重放，响应策略承担业务错误校验。本次发现两类可以移除的
额外工作：旧式列表转换仍绕过共享标量编码器；响应收集即使只有一个数据块
也会复制完整正文。两处已统一到共享实现中。这两项属于性能类信息性发现：原行为正确，实测额外开销支持本次定向重构。

| 共享路径 | 决策与依据 |
| --- | --- |
| 公开接口适配与兼容辅助方法 | 保留类型化参数和薄 future，复用统一客户端，没有 boxed future 分配或额外 runtime。 |
| `call_with` / `execute` / `attempt` | 保留 key 类型隔离、无查询参数的 URL 缓存、AWS-LC 连接池、整体预算、信号量、节奏和冷却；本次没有增加重试或主机回退策略。 |
| 响应策略及类型化/opaque 解码 | 保留完整标准错误外层检查和自有数据解码；各协议的确认规则继续执行。 |
| CSV 与数字后缀字段 | 用户/应用过滤与资产字段直接写最终表单，移除临时标量字符串、collect/join 容器及逐资产格式化键。 |
| HTTP 正文收集 | 单块直接持有原始数据块，第二个非空块到来时才合并，保留流式长度检查及受限容量提示。 |

## 请求编码

[`CommaSeparated`](../src/request.rs) 为借用的标量切片实现已有私有 `FormValue`
契约，逐项写入最终表单，项目之间写 `%2C`，与先按逗号拼接字符串再进行表单
编码的字节完全一致。空元素、Unicode、NUL、百分号与完整宽度整数保留原有
表示。Publisher 应用类型通过既有字符串映射使用相同标量契约。

生产调用覆盖资料/封禁批次、应用价格和 Publisher 应用过滤。旧式资产购买也
统一使用已有 `push_suffixed` 生成 `assetid0`、`assetquantity0`，每个资产省去
两个 `format!` 临时字符串。参数校验、字段顺序与端点策略保持一致，由标量/
表单等价测试和已有接口协议测试核对实际字节及语义参数。

## 有界响应所有权

私有 [`ResponseBody`](../src/body.rs) 包含三个状态：

| 状态 | 下一个非空数据块 |
| --- | --- |
| Empty | 接管数据块所有权。 |
| Single | 分配连续缓冲区，复制两个块，释放第一个块的所有权。 |
| Buffered | 追加到已有缓冲区。 |

每次追加均在修改状态或复制之前检查合计字节数，空块保持当前状态。只有需要
合并时才使用长度提示预留空间，继续保持原有 64 KiB 提示上限。响应头与流式
长度检查返回同样的公开错误；JSON、业务校验及 DTO 解码接收完全相同的正文。

单块路径省去独立正文 `Vec` 分配和完整复制。多块仍需合并，转换时前两个传输
块及目标缓冲区可能短暂共存。配置限制仍约束逻辑正文长度，不代表整个进程的
内存上限。收集器不持有任务、凭据、连接或共享同步状态。

## 可复跑测量

```sh
cargo bench --bench request --locked --offline -- --lists-only
cargo bench --bench codec --locked --offline -- --body-only
```

基线复现 `9d2cab1` 的算法，候选直接包含生产源码模块。测试数据在计时外构造，
先核对表单字节及解码模型相等。每项运行九轮 A/B/B/A，分别取 18 个样本中位数，
基线漂移超过 10% 即拒绝解释。本次全部通过，基线绝对漂移最大 1.4%；计时包含
输出析构。

这是共享开发机器上的本地 release CPU 测量，使用独立 Cargo target，
本任务的构建与计时串行执行。请求项排除参数校验与 HTTP；正文项给两个算法相同的自有
`Arc<[u8]>` 测试块，不包含真实 HTTP 到达及传输缓冲分配。完整响应项包含正文
组装、JSON、错误检查、外层选择、类型化解码及析构。网络/TLS 延迟、Steam
配额和生产吞吐需要单独测量。

| 编码项 | 基线 ns/op | 重构后 ns/op | CPU 时间减少 | 基线漂移 |
| --- | ---: | ---: | ---: | ---: |
| 单个完整宽度 SteamID | 70 | 27 | 61.2% | -1.4% |
| 100 个完整宽度 SteamID | 3,750 | 757 | 79.8% | -0.4% |
| 六种 Publisher 应用类型 | 89 | 54 | 39.8% | +0.3% |
| 100 条旧式资产参数 | 5,922 | 2,666 | 55.0% | -1.4% |

| 响应项 | 基线 ns/op | 重构后 ns/op | CPU 时间减少 | 基线漂移 |
| --- | ---: | ---: | ---: | ---: |
| 64 B 单块组装 | 21 | 8 | 62.4% | +0.6% |
| 4 KiB 单块组装 | 73 | 5 | 92.7% | -0.6% |
| 64 KiB 单块组装 | 672 | 4 | 99.5% | -0.2% |
| 64 KiB / 四块，已知长度 | 919 | 849 | 7.5% | +0.4% |
| 64 KiB / 四块，未知长度 | 1,420 | 1,159 | 18.4% | -0.5% |
| 完整类型化响应 / 单块 | 25,052 | 23,700 | 5.4% | -0.2% |
| 完整类型化响应 / 8 KiB 分块 | 25,163 | 25,296 | -0.5% | -0.0% |

ns 为四舍五入结果，比例由未舍入中位数计算。保留单块的组装工作与正文大小
无关，因此组装阶段的改善比例很大。完整多块解码本次基本持平，实测慢 0.5%。
这些结果仅支持表中工作负载，不应换算为应用或网络吞吐倍数。
