# 0.5 Financial reporting, site licensing and broadcasts

English | [简体中文](p4_ZH.md)

P4 adds six methods and closes binding coverage for the documented 33-interface
snapshot: 167 routes, consisting of 157 explicit signatures and ten inherited
Sandbox routes. This is HTTP protocol coverage; production permissions, private
APIs and native SDK capabilities are separate. The [roadmap](roadmap.md) and
[machine inventory](api-inventory.json) retain those boundaries.

## Financial authority and reporting

[IPartnerFinancialsService](https://partner.steamgames.com/doc/webapi/IPartnerFinancialsService)
uses a dedicated Financial API Group key with partner-wide visibility, including
all applications and authorized view grants. Use `ApiKey::financial(...)` in a
separate trusted-backend client; User and Publisher keys do not satisfy its local
access rule. Financial keys also cannot authorize other endpoint categories here.
Declaring the kind does not prove Steam permissions. Configure the group and its
IP allowlist in Steamworks. The key remains zeroized/redacted and travels in the
sensitive `x-webapi-key` header, outside `input_json`.

All three methods are GET with exact `v001` spelling. Service JSON encoding is
supported by the [overview](https://partner.steamgames.com/doc/webapi_overview).
Read retries remain bounded; clients never switch hosts or fetch another page
automatically. Financial clients default to Partner.

The two sales cursors have distinct responsibilities:

1. GetChangedDatesForPartner starts with `highwatermark=0`. A date can recur after
   settlement or recalculation, including dates already processed.
2. For each returned date, restart GetDetailedSales at `highwatermark_id=0` and
   rebuild that date's complete local snapshot. Continue with its returned max_id.
3. A date finishes when returned max_id equals the input cursor. Empty or short
   results alone do not establish completion.
4. Save the outer result_highwatermark only after all dates have succeeded. The
   crate does not persist cursors, replace records or combine partial snapshots.

The outer cursor stays an exact string. The per-date cursor accepts int64 or its
decimal text; negative values must not be cast to uint64. Request cursors remain
uint64 and the caller performs checked conversion. Sales dates use Pacific Time,
while wishlist dates use GMT. Accepted calendar date spellings remain unchanged;
no UTC conversion or invented reporting interval occurs.

Local prices retain uint64 cents. USD values retain their original signed decimal
strings; unit counts and categories follow the documented integer/string types.
Conditional package, microtransaction and key fields stay optional, and unknown
metadata/lookup arrays remain in `extra`. Out-of-range wishlist responses can
contain only app_min_date, without inventing zero activity. Debug output hides
dates, cursor values, money, names and unknown fields. These sales aggregates do
not establish payment authority or replace official payout reports.

The [example](../examples/financial_changed_dates.rs) reads one batch and prints
only its date count. It does not log financial values, advance a cursor or read
an account without the caller explicitly supplying a Financial key.

## Site activity and report intervals

[ISiteLicenseService](https://partner.steamgames.com/doc/webapi/ISiteLicenseService)
has two Publisher GET methods. Its method URLs show the Public host; configure
`host(Host::Public)` to match them explicitly. The overview recommends Partner
for secure Publisher backends, which remains the default. Selection is fixed
and no automatic cross-host fallback occurs. Service arguments use `input_json`.

Omitted siteid and explicit zero both select all authorized sites; nonzero filters
are not broadened. `game_names.id` and each game record's id are response-local
dictionary keys, not app IDs. Site IDs preserve uint64 numbers/strings; playtime
seconds retain uint32. License strings recognize user/commercial/free while
preserving future values. All nested unknown fields remain available and Debug
redacts private site names, IPs, hostnames and extension data.

GetTotalPlaytime selects sessions starting in `[start_time, end_time)`, without
inferring clipping of overlapping sessions. UTC validation and ordering handle
different equivalent suffixes and arbitrary fractional precision without floats
or raw-string comparison. Equal boundaries remain an empty interval. Original
timestamp text is sent unchanged, and no report splitting or polling is inferred.

The Site page lists response fields without a complete JSON wrapper example.
Typed models use the canonical `response` envelope with sites/game_names arrays;
wrapper and omission conventions remain subject to credentialed validation.
Missing arrays are schema failures, not fabricated empty site reports.

## Broadcast frames

[IBroadcastService](https://partner.steamgames.com/doc/webapi/IBroadcastService)
adds PostGameDataFrame v1 using Publisher credentials and `input_json`. The frame
is an opaque UTF-8 string, including empty or embedded-NUL input. The crate does
not parse it as JSON, assume base64, impose an undocumented payload cap, start a
broadcast or infer delivery. POST is single-send even after 429, 503 or timeout;
the undocumented response schema remains opaque and redacted.

## Coverage, validation and distribution

```sh
cargo xtask coverage
cargo xtask coverage --json
cargo xtask check-repository
```

The report derives counts and remaining routes from the inventory, checks public
exports, method declarations and exact path literals, and matches inherited
Sandbox signatures to their production originals. Static source mapping is not
AST analysis, a live API probe or proof of operation. Protocol fixtures are a
separate validation layer. CI stores the JSON in `steam-api-web-coverage`.

Local validation includes 210 workspace tests, complete P4 route/encoding/key
checks, error and replay fixtures, date boundaries, integer extremes, privacy,
coverage guards and existing transport regressions. Independent review found no
additional concrete contract defect. No real financial, site or broadcast data
was accessed. Credentialed authorization and production behavior remain untested.

Cargo's explicit include allowlist contains sources, examples, bilingual README/
changelogs, license and Cargo metadata. Tests, benchmarks, xtask, workflows, these
docs and reference JSON stay on GitHub. The project contains no Python source and
keeps the existing per-client AWS-LC backend with no new dependencies. Version
0.5.0 remains unreleased; tag creation and publishing are separate actions.

The [0.5 branch review](review-0.5.md) records shared integer decoding, regression boundaries and scalar measurements.
